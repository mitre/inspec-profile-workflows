# InSpec Profile Workflows

Reusable GitHub Actions workflows for building and publishing InSpec/CINC-Auditor profile archives. This repository shares complete workflows, not a Marketplace action.

## Build and release a profile

The [release workflow](.github/workflows/release.yml) checks out the **calling profile repository**, installs its Gemfile, and builds one archive named `<name>-<version>.tar.gz` using the values in `inspec.yml`.

1. Build and validate the archive, including vendored profile dependencies when declared.
2. Generate its SHA-256 checksum and upload both files as the `release-profile` Actions artifact (retained for 14 days).
3. On an eligible push, wait for approval in the calling repository's `Release` environment.
4. Download and verify that same artifact, then create `v<version>` at the original build commit and attach the archive and checksum. Release notes are generated by GitHub.

Approving publication does **not** rebuild the archive. Pull requests build and validate only. Publishing is disabled by default.

## Add it to a profile repository

First commit and push this shared workflow. Then copy [examples/release.yml](examples/release.yml) to the profile's `.github/workflows/release.yml`, replacing `WORKFLOW_COMMIT_SHA` with the full published commit SHA from **this repository**. The example is ready for the Debian 11 fork; it is not an active workflow in this repository.

Before enabling publishing:

- Configure **Settings → Environments → Release → Required reviewers** in each profile repository. The publishing job fails if reviewers are missing or its token cannot read the environment's protection settings.
- Ensure the repository/organization permits the referenced workflow and actions. If this shared repository is private, configure Actions access for the callers; a public repository is needed for unrelated public callers.
- Have a root-level `Gemfile` that installs the selected auditor and an `inspec.yml` with a filename-safe `name` and an `X.Y.Z` version.
- Allow the caller's token `contents: write` and `actions: read`, as shown in the example. The build job explicitly uses only `contents: read`; write access is used by the publishing job. No personal access token or `secrets: inherit` is needed for public profile dependencies.
- Check whether required reviewers are supported by your GitHub plan and repository visibility.

For an artifact-only trial, set `publish: false` (or omit it). For an InSpec-based profile, set `auditor: inspec`; the default is `cinc-auditor`.

## Inputs and outputs

| Input | Default | Purpose |
| --- | --- | --- |
| `auditor` | `cinc-auditor` | Executable installed by the profile's Gemfile: `cinc-auditor` or `inspec`. |
| `ruby-version` | `3.3` | Ruby version used for the build. |
| `publish` | `false` | Enable approval-gated publication on eligible pushes. |
| `release-branch` | `main` | Branch allowed to publish; the caller's push trigger must include it. |

Outputs: `archive` (filename) and `tag` (for example, `v0.1.0`). One profile invocation per workflow run is supported; artifact names are shared within that run.

## Versions, approvals, and offline use

Update `version` in the profile's `inspec.yml` before a new release. The workflow code's commit SHA, the profile build's commit SHA, and the archive's SHA-256 checksum identify different things: workflow implementation, profile source, and asset contents.

The tag is created during publication, after approval. An existing tag must resolve to the build commit. An existing release is not overwritten; a rerun that reaches release creation fails if that release already exists. No tags or releases are created for pull requests.

Approve the pending `Publish Approved Release` job from the profile repository's Actions run. This is approval of the existing build, not a manual dispatch that builds again. Approve before the artifact expires; an expired artifact requires a new build. Configuring reviewers is a repository setting and is not done by this workflow.

Dependencies do not need to be committed under `vendor/`: the archive command vendors them at build time. Profiles without dependencies are supported without requiring a vendor directory. Archive validation is a structural check, not a live compliance scan or proof of offline execution.

The archive includes profile dependencies, **not** the InSpec/CINC runtime or its Ruby gems. Air-gapped runners must already have the required runtime, including any custom InSpec fork, installed. Private dependencies and runtimes with licensing requirements need their own authorized setup; this workflow does not provision credentials or licenses.

## Development

Run the local workflow tests with:

```sh
ruby test/release_workflow_test.rb
```

Tests exercise the embedded metadata and shell steps with fixtures and mocked external commands; they do not publish releases. A real GitHub run is still needed to validate environment approvals and cross-repository access.

See GitHub's [reusable workflow documentation](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows).
